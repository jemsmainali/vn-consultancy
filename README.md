# VN Group — Student Portal and API

A FastAPI backend and React website for student enquiries, document uploads, and
secure messaging with consultancy staff. Important account and document actions
are recorded in the audit log.

## Folder structure

```
consultancy-app/
├── app/
│   ├── main.py              # app entrypoint, CORS, security headers, routers
│   ├── core/

│   │   ├── database.py      # async SQLAlchemy engine/session
│   │   └── security.py      # password hashing + JWT create/verify

│   │   ├── document.py
│   │   ├── message.py

│   │   ├── deps.py           # get_current_user, require_role
│   │   ├── auth.py           # register / login / refresh
│   │   ├── documents.py      # upload / list / review documents
│   │   └── messages.py       # send / read messages

├── requirements.txt
├── .env.example
└── .gitignore
```

## Setup

1. **Create a virtual environment and install dependencies**
   ```bash
   python3 -m venv venv
   source venv/bin/activate       # Windows: venv\Scripts\activate
   pip install -r requirements.txt
   ```

2. **Install `libmagic`** (needed by `python-magic` for real file-type sniffing)
   ```bash
   # Debian/Ubuntu
   sudo apt-get install libmagic1
   # macOS
   brew install libmagic
   ```

3. **Set up PostgreSQL** and create a database + user matching your `.env`.

4. **Configure the environment**
   ```bash
   # Bash: create a local file only when one is not already present.
   [ -e .env ] || cp .env.example .env
   # Generate a real secret key:
   openssl rand -hex 32
   ```
   In PowerShell, use `if (!(Test-Path .env)) { Copy-Item .env.example .env }`.
   Keep existing `.env` values; never replace a configured file with the template.
   Add the generated value and your PostgreSQL connection details to `.env`. Never commit `.env`.

5. **Check and apply the existing migrations**
   ```bash
   alembic current
   alembic upgrade head
   ```
   The project already has migration history. Do not create another initial migration. Review
   any future autogenerated migration before applying it to a database with student records.

6. **Run the app**
   ```bash
   uvicorn app.main:app --reload
   ```
   Visit `http://localhost:8000/docs` for interactive API docs (disabled
   automatically when `ENVIRONMENT=production`).

7. **Run the React website** (in a second terminal)
   ```bash
   cd vn-frontend
   npm install
   npm run dev
   ```
   Vite serves the website at `http://localhost:5173`. Set `VITE_API_URL` in the frontend
   environment when the API is not at `http://127.0.0.1:8000`. Only public URLs belong in
   frontend environment variables; the browser bundle cannot protect secrets.

## Website pages

The public website includes home, about, destinations, student journey, FAQs, contact, and
privacy/data pages. Contact enquiries are saved in PostgreSQL and receive a reference only
after a successful save. Staff manage them at `/leads`; the API is `POST /enquiries` and
staff-only `POST /enquiries/staff/search`, `GET /enquiries/staff/{id}`, and
`PATCH /enquiries/staff/{id}`. Search terms are sent in a JSON body instead of the URL.
The student portal is at `/portal`; messaging and
profile routes remain `/messages` and `/profile`. Staff pages remain `/approvals`, `/users`,
and `/audit-log`.

Destination notes are introductory only. Confirm current tuition, entry, scholarship,
employment, and visa information with the relevant university and official authorities.
The current registration form collects personal and identity information, and the Terms
page still contains placeholder language. The privacy/data page describes verified current
software behavior, including that there is no automatic retention schedule. Obtain approved
privacy/terms information and define retention practices before using registration or
enquiries with real students.

## Production frontend build

```bash
cd vn-frontend
npm ci
npm run build
```

Deploy the generated `vn-frontend/dist` files on the existing static hosting platform with
history fallback enabled for React Router routes. Configure `VITE_API_URL`, backend CORS
origins, `COOKIE_SECURE=true`, and HTTPS for the actual production domains. No hosting
platform or domain is configured in this repository.

## Roles

- **`student`** — registers, uploads documents, sends/receives messages, sees only their own documents.
- **`consultancy_staff`** — sees every submitted document, updates document status, messages students.

Set the role at registration time via the `role` field (in a real product
you'd likely restrict who can register as `consultancy_staff` — e.g. an
invite-only signup or manual promotion by an admin, rather than a public
open field).

## Core endpoints

| Method | Path | Who | Purpose |
|---|---|---|---|
| POST | `/auth/register` | anyone | create account |
| POST | `/auth/login` | anyone | get access + refresh token |
| POST | `/auth/refresh` | anyone (with valid refresh token) | rotate tokens |
| GET | `/auth/me` | logged-in | current user info |
| POST | `/documents/upload` | student | upload a document (multipart/form-data) |
| GET | `/documents/mine` | student | list own documents |
| GET | `/documents` | staff | list every submitted document |
| GET | `/documents/{id}` | owner or staff | view one document's metadata |
| PATCH | `/documents/{id}/status` | staff | mark reviewed/rejected |
| POST | `/messages` | logged-in | send a message |
| GET | `/messages/thread/{other_user_id}` | logged-in | view a conversation |
| PATCH | `/messages/{id}/read` | receiver only | mark a message read |

## Security measures already built in

- Passwords hashed with bcrypt (`passlib`), never stored or logged in plaintext.
- JWT access tokens are short-lived (20 min default); refresh tokens rotate on use.
- Login/register endpoints are rate-limited (`slowapi`) against brute force.
- Uploaded files are validated by **sniffing actual file bytes** (`python-magic`),
  not trusting the filename or client-supplied Content-Type — this stops someone
  renaming an executable to `.pdf`.
- Uploaded files are stored under randomly generated names, never the
  user-supplied filename, which prevents path traversal and overwrite attacks.
- File size is capped (`MAX_UPLOAD_MB`) before it's ever fully processed.
- CORS is restricted to an explicit origin list — never `*` — configurable per environment.
- Every document/message state change writes to an immutable `audit_logs` table.
- Interactive API docs (`/docs`) are automatically disabled when `ENVIRONMENT=production`.
- Basic security headers (`X-Content-Type-Options`, `X-Frame-Options`,
  `Strict-Transport-Security` in prod) added to every response.
- Login errors never reveal whether the *email* or the *password* was wrong.

## What you still need to do before going to production

- **Serve behind HTTPS** (e.g. via Nginx + Let's Encrypt, or your cloud provider's
  load balancer). JWTs sent over plain HTTP are trivially stolen.
- **Move file storage to S3 or similar** once you're off a single server —
  local disk storage doesn't survive redeploys or scale across instances.
- **Add a token-revocation/blocklist mechanism** (e.g. store `jti` of
  logged-out or compromised tokens in Redis) if you need to force-expire
  sessions before their natural expiry.
- **Restrict `consultancy_staff` registration** — right now anyone can pick
  that role at signup; lock this down (admin-approved invite, or a separate
  internal-only registration endpoint).
- **Add structured logging + monitoring** (e.g. Sentry) so failed logins,
  5xx errors, and rate-limit hits are actually visible to you.
- **Back up the database** on a schedule — this holds every student's
  application documents and records.
- **Add virus/malware scanning** on uploads (e.g. ClamAV) if you'll accept
  files from the general public, not just verified students.
